# Test2 EP01 G4 production plan

Production completed in the later manually supervised assignment; see
`docs/ops/2026-09-27-test2-ep01-g4-production-result.md` for the final artifact,
runtime measurements, cost, quality boundaries, and verified shutdown. The
session-specific authorization notes below describe the historical gates.

This plan is specific to the 2026-09-25 Test2 EP01 manual-call pack. It depends on the G4 restore/setup baseline in this branch and does not modify the reusable pack-audit skill. The source ZIP and original jobs remain immutable; U05 uses the separately reviewed independent-start candidate.

## Frozen input and graph gates

- Freeze the eight selected job directories and their SHA-256 manifest before any paid assignment. Select original U01-U04 and U06-U08, but the `U05-independent-candidate` job. Upload the small job archive to Drive once; model/runtime restore continues to use the existing verified G4 snapshot.
- Preserve 15.083 seconds, 24 fps, 9:16, 1.0 MP, one pass, 12 sampler steps, SageAttention SM120, original reference bytes, and original dialogue. Do not silently convert `duration_seconds` to an integer.
- Motion-latent chains are `U01 -> U02 -> U03 -> U04` and `U05 -> U06 -> U07 -> U08`. U01 and U05 save a latent without loading one. Every other unit loads the immediately preceding verified latent. Never submit an EP01 U05 graph with U04 LoadLatent.
- Submit exactly one prompt per unit. Confirm the server history, output video and latent, audio, graph, telemetry, and Drive receipt before submitting the next unit. An uncertain prompt is reconciled, not retried blindly.

## Runtime and quality

1. Perform local no-pay graph/input dry-runs, verify current Colab account is idle and Drive has capacity, then create the user-authorized first G4 assignment with a 40 CU / 4-hour ceiling and an independent watchdog. If incomplete at that limit, stop, reconcile outputs and billing, and seek approval before any additional paid assignment.
2. Restore and preflight the existing G4 environment; install only the frozen EP01 job archive. Record GPU identity, runtime/model hashes, transfer and setup time, usage rate and balance.
3. Produce U01 first and inspect sampled frames/audio for identity, spatial integrity, and unintended four-grid split before continuing. Review U04 action coverage before crossing the scene cut. Review U05's first second for a clean hall start and U06's first second for handoff continuity.
4. Archive each unit's MP4, raw AV latent, prompt, submitted graph, logs, timing, telemetry, and validation receipt to Drive. Keep the Colab instance alive only while useful; always stop and verify zero active assignments and zero usage rate.
5. Assemble the final EP01 edit from the verified unit MP4s. The existing MotionContextTrim node removes the parent-overlap frames from U02-U04 and U06-U08 during rendering; do not trim those MP4s a second time. U05 is an independent start. Make U04/U05 a direct narrative cut. Check final A/V duration, playable MP4, ordered shots, dialogue, and Drive SHA-256 before declaring completion.

After U01 recovery and all U02-U08 unit receipts are verified and the paid assignment has stopped, run
`PYTHONPATH=src:scripts/ops ../../.venv/bin/python scripts/ops/h3_test2_ep01_finalize.py --session <session> --resume-u01`
from the isolated worktree. It downloads only the eight verified MP4s (not AV
latents), concatenates them with stream copy, decodes the full output, compares
frame count and A/V duration, and uploads `final/EP01-test2-v1.mp4` plus a
terminal receipt under that session's Drive run prefix. The command must not
replace visual review of the scene cut and character continuity.

## First-session transport finding

The first G4 assignment `h3-test2-ep01-20260927-091720` stopped before restore or any prompt: `colab upload` did not return for the 32 MiB `rclone.gz` within 300 seconds. The CLI implementation base64-encodes an entire uploaded file into one Jupyter Contents API request; a 4 MiB chunk also remained pending for over two minutes in a CPU diagnostic session. Do not repeat that transport path.

The replacement transport uses a small CLI-uploaded `rclone.conf`, installs the distro `rclone` in the runtime, fetches the already SHA-256-verified SageAttention wheel directly from Drive, and prepares the gzip wrapper expected by the unchanged restore script. The CPU diagnostic verified Drive access, wheel SHA-256, and the restored executable; that session was stopped at zero usage rate (about 0.01 CU). The G4 host now rejects any CLI upload over 256 KiB before starting a paid assignment. A new G4 assignment requires separate confirmation under the user's first-session renewal rule.

## Fifth-session Colab transport loss

The explicitly authorized assignment `h3-test2-ep01-20260927-160900`
confirmed the runtime's apt client is `rclone v1.60.1-DEV`, matching the
locally reproduced missing-SHA-256 behavior. All six models restored in
826.31 seconds. Immediately afterward, the CLI lost its Jupyter connection
while running its own `runtime.execute_code("...os.chdir('/content')")`
prologue for the setup stage. The setup script had not begun: its log contains
no `RUN` command or ComfyUI marker. The host conservatively stopped instead
of retrying; U02 was not submitted. Balance moved from 137.04 to 134.80 CU
(about 2.24 CU), with shutdown verified at 0 active assignments and 0.00
CU/hour.

The Test2 host now retries a stage only once when the CLI traceback proves
the failure happened in that pre-execution prologue and no script `RUN` output
exists. It retains the first traceback as `*-preexec-lost.log`. A loss after
script execution begins is never retried, and unit-generation phases continue
to use receipt reconciliation without blind resubmission. This protects the
already restored 45 GiB models against a transient pre-script WebSocket loss
without changing generation semantics. Another paid assignment still needs
separate authorization.
