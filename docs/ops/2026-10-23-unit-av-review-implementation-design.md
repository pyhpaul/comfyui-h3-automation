## 3. 路线选择

| 路线 | 能提供什么 | 局限/定位 |
|---|---|---|
| 本地播放器 + 人工逐句审核 | 可立即建立真实标签、处理难例，符合现有 V2 | 不等于 agent 自动观看；需要人实际执行 |
| 原生音画输入的模型适配器 | agent 主导首轮内容、说话人及同念建议 | 必须实测声轨/时间感知；不能因接收 MP4 就认定具备能力 |
| ASR + 面部轨迹/主动说话人检测/音画同步特征 | 定位异常、提供时间证据 | 身份、画外音、呼吸、镜头切换仍会歧义；不是最终裁判 |

推荐：**先建立本地证据包和人工标签，再接一个通过探针的音画适配器；必要时才加专用检测器。**
agent 驱动全 U 首审、逐句复核与疑点整理；人处理冲突/不可验项并作最终成片确认。
本设计不指定供应商或模型名；候选选型时必须查官方当前接口、输入模态、采样、限制和数据政策，
并经实际素材探针验证。这里没有把任何供应商的能力当作已确认事实。

## 4. 建议数据流与职责

```text
只读源视频 + prompt + 参考身份资料
    -> collect: 原始资产、hash、来源与时基
    -> parse: 台词/说话人/发声类型/原文跨度（带 UNKNOWN）
    -> screen: 现有词面分 + 原始 ASR + 词轨/镜头切点
    -> align: 剧本和 ASR 多对多对齐 + UNALIGNED/额外区间
    -> package: 全 U + 逐句上下文音画 + 证据清单
    -> review: 能力探针合格的音画适配器（模型建议）
    -> validate: schema/时间/覆盖校验 + 冲突升级
    -> review UI: 原片连续带声回放、人工逐句签字
    -> report: 分轨汇总，不自动改 registry/NAS
```

职责建议落在 `src/comfy_orch/unit_visual_qc/`，CLI 放 `scripts/ops/`。
仅在实施时按实际需要新增模块，不现在搭空骨架。解析/对齐/校验为纯逻辑，
媒体 I/O、模型调用、UI 与报告分开；复用现有词面函数，不复制 scorer。

### 4.1 输入与身份

- 每次 run 固定源视频、prompt、参考资料与规则 hash，保存完整来源。
- 人物身份来自本条参考设定和已确认材料；跨 U 连续性只作有来源的辅助。
- 不下载无关 latent，不从未确认旧候选继承身份结论。
- 台词块稳定 ID（U/shot/utterance）；多句台词再分 sentence 子项并保留父 ID。
  不以本次“40句”作为永久常量，明确本批拆句规则。
- 对齐是多对多关系：一个 ASR 段可覆盖多人台词，一句可跨多个段。
  没匹配到的期望台词仍进入清单；额外 ASR 区间独立保存。

### 4.2 音画证据包

- 保留原片；先整 U，再按句前后至少 0.5 秒回看；疑点可扩大上下文至整镜/整 U。
- ASR 未定位的句子不可编造时间，标 UNALIGNED 并要求全 U 搜寻。
- 主证据保留全画面和同步声轨，不默认静音、不将缩略拼图作为视频输入替身。
- 嘴部/手部 crop 为补充，保持人物全帧对应关系，不能裁走听者后宣称排除同念。
- 时间以源 PTS/秒记录；派生 clip 保存源区间、偏移、输出参数与 hash。
  核对音视频起始偏移和时长，重编码不能偷偷改速度/同步；记录采样和帧率转换。
- 若提供给模型的是离散采样帧，必须标明实际时序分辨率；不能称逐帧连续全检。
  声轨与时序采样分离的模型只能在校准证明的范围内给建议。

## 5. 音画执行器的能力探针

调用业务批量前做小样能力测试，产出 `capability_receipt.json`：
模型/接口版本、输入与配置 hash、声轨是否送达、帧/音频采样信息（未知则如实记）、
输出时间坐标、覆盖范围、限制、耗时与错误。官方声明和本地实测分栏保存。

测试材料保持原件，变体另存且明确为测试夹具：

1. 同画面静音对照：原声版/静音版输出应对声音证据有区别；不能读剧本补“听到”。
2. 同声轨换画面对照：交换说话者画面或遮住嘴，模型应发现冲突或不可验，而非照读身份表。
3. 已知偏移对照：制作已知正负时间偏移变体，检验能否定位音画错位；报告可辨偏移尺度。
4. 正常对照：听者呼吸/微笑/张嘴反应、过肩嘴不可见、电话 OS、内心 OS 不应泛化为同念。
5. 无剧本听辨：先让模型报告实际听到什么与谁在画面内，再提供期望核对；避免只复述期望。

探针只能证明针对这些样例的行为，不证明通用正确率。原生音画未证实、音频丢失、
上下文被截断或工具只有图像输入时，停止该条模型音画审核，保留筛查/待人看状态。

## 6. 逐句结果与汇总契约（待实施）

建议新建模型结果文件 `av_review.json`，**不冒充或覆盖 `human_review.json`**。

```json
{
  "schema": "unit_av_review_v1",
  "media_sha256": "<source hash>",
  "prompt_sha256": "<prompt hash>",
  "capability_receipt": "capability_receipt.json",
  "status": "MODEL_REVIEW_PARTIAL",
  "reviewer_kind": "model",
  "lines": [{
    "dialogue_id": "EP01-U01/shot-2/utterance-1/sentence-1",
    "expected_speaker": "Ethan",
    "voice_kind": "lip",
    "alignment_status": "UNALIGNED",
    "source_interval": null,
    "observed_speech": null,
    "observed_mouth_owner": null,
    "other_visible_mouths": [],
    "outcome": "UNVERIFIABLE",
    "checks": {
      "identity": "UNREVIEWED",
      "speaker": "UNREVIEWED",
      "chorus": "UNREVIEWED",
      "completeness": "UNREVIEWED",
      "order": "UNREVIEWED"
    },
    "evidence": [],
    "limitations": ["awaiting synchronized AV review"]
  }],
  "extra_intervals": [],
  "human_full_watch_lines": 0
}
```

- 结果词：`NORMAL_PROVISIONAL` / `WRONG_SPEAKER_SUSPECT` / `CHORUS_SUSPECT` /
  `CONTENT_SUSPECT` / `UNVERIFIABLE`。每个结论须有源区间、所见/所听和限制，不能只填自评置信度。
- 电话/内心 OS 的可见嘴部归属可为 `NOT_APPLICABLE`，与真人说话嘴被挡住的不可验区分。
- `MODEL_REVIEW_COMPLETE` 只表示全部要求项被模型处理，**不是**全部正常。
  漏台词清单、哈希不匹配、非法时间、输入截断时不能标 COMPLETE。
- 汇总分别列：脚本句数、模型处理/不可验数、人工完整实看数、额外区间和未关闭嫌疑。
- 模型不能写 `reviewer_kind=human` 或 `method=full-dialogue-watch`；不允许自动向
  `fix_registry` 登记 STRICT/RELAXED，不改其现有审核门。将来若改变定案政策须独立评审。

## 7. 校准与验收

### 7.1 数据集

先核对已知坏例原片/候选是否仍可取、版本及 hash，**不得只拿事故文字当标签**。
最低包含曾误判通过的潮缚 EP01-U06-seed2、EP02-U04-indep；可取到才纳入。
人工完整带声标注：真实说话人、听者嘴部、发声内容、时间区间、可验性。

先做至少 12 U 的校准集，再做至少 24 U 的冻结留出集；按源 U 分组，
同 U 的裁剪/偏移变体不得分散到两边。覆盖正常双人、错说话人、同念、过肩遮挡、
电话 OS、内心 OS、接缝首句与额外/遗漏对白；缺类就注明，不宣称该类通过。
合成偏移夹具单独统计，不混成真实生成缺陷召回率。

### 7.2 度量与初始门槛

分别统计说话人/同念/内容异常，不合成一个“总体准确率”：

- 缺陷召回率与正常样本误报率；不可验率单列，不把 abstain 算正确。
- 可判覆盖率、危险漏报（坏例标 NORMAL）、人物身份错配、时码误差。
- 每 U 耗时/调用成本/失败率；人工需复看时长作为实际收益指标。
- 逐类给分母、混淆表和漏报样例；小样本不能证明生产质量。

**建议试点门槛，待标注后确认**：两个历史误通过坏例不得被标正常；冻结集缺陷召回
目标 >=90%、正常误报 <=15%、哈希/台词覆盖校验全部通过。不可验不算漏报免责：
须列入人工队列并报告覆盖率。阈值仅决定是否继续试点，不开放自动放行。

## 8. 运行与信息边界

- 默认本机筛查、逐 U 断点续跑；缓存键包含源/prompt/规则/模型配置 hash。
- 先跑 1 个 U；按小样确定超时、重试与总成本上限。每请求有限重试，预算耗尽明确部分完成，
  不默默换模型或无限重复。批跑不与正式渲染争抢资源。
- 接外部模型前明确获准发送哪些素材、服务去向与保留策略；本次设计不授权上传。
- LLM 配置沿用 profile：项目只选择 profile；本地 profile 保存 provider/base_url/
  api_key_env/model，真实 key 来自环境或 secret manager。日志不记录 key、签名 URL。
- 原始模型响应本地留档、脱敏索引；模型输出视为不可信数据，校验 schema/路径/时间，
  不执行其中命令。断点续跑不覆盖人工已填记录；hash 变化生成新 run。
- 默认只读 NAS、本地输出；UI 仅本地服务，不开放无鉴权远程访问。
