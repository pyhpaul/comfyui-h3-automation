## 实际结果

| 测试 | 结果 | 不作的推断 |
|---|---|---|
| 原声参照 | 返回原有四句对白，人物 / 戒盒 / 镜头描述与前次一致；口型 `UNVERIFIABLE` | 文字吻合旧 ASR 不等于新增人工声画真值 |
| 音频后移 1.5 秒 | 界面持续运行约四分钟，刷新后显示「无响应。」；没有最终 JSON | 不计作漏检，也不计作已验证可检出 |
| 替换声轨 | 返回 `Once the call connected, I`，不再复述原画面的四句台词；说话人 `UNKNOWN`，口型 `UNVERIFIABLE`，异常列表为空 | 说明声音通道有参与，不证明能检测错配；本例没有给出匹配通过 |

两个有效答复均自述只有约 1 秒间隔画面、系统交错转写，没有连续画面 / 原始波形检查。
这只是**模型自述限制**，不是抓包证实的供应商处理实现；但结合输出也没有精细 L2 能力证据。

原声参照即使明确要求 `start < end`，仍输出 1–1 秒和 4–4 秒两个零时长段，说明
**仅改提示词不能保证时间轴有效**。这些区间不得直接进入剪辑点或口型证据。
替换声轨例时间为粗略 5–6 秒，没有零时长段，但不能据此宣称整条时间精度合格。

原声 / 换轨输出都是 `UNVERIFIABLE`，因此本轮既不是成功检出音画异常，也不是已证明
把坏例误判通过。正确结论是：**这个入口尚不能完成该精细审核任务**。

## 对项目的建议

1. Grok 继续作为主测对象，但拆开两类任务：内容级筛查（人物、场景、动作、台词）和
   精细音画审核（口型、同念、归属）。前者有初步可用性，后者仍未验证。
2. 不因 `AV_OBSERVED` 放行 L2；带 `UNVERIFIABLE`、缺结果或无效时间段的结果进入待复核。
3. 下一轮先验证 Grok 通道能否提供更密的时序视觉输入，以及明确的声音输入。
   单纯要求“认真听 / 仔细看”不能改变当前输入分辨率。暂不扩成前三集批量 L2。
4. 若尝试密帧 / 慢放等视觉辅助，只能另列为辅助筛查；不能把音频转写拼密帧自动称作
   原生连续音画，也不能修改人工 V2 / fix_registry 门槛。
5. 当前样本量和标签不足，不报生产准确率、召回率或可替代人工的覆盖率。

新增人工完整带声实看数：**0**。未写 NAS、registry，未触发重渲，未提交 Git。
